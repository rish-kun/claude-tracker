Set up cctrack

cctrack shows how much of each shared Claude plan every teammate uses. You deploy the dashboard once; each teammate then installs a small CLI and the Claude Code plugin. Tick each step as you finish it. Your progress stays in this browser.

You, once

About 20 minutes. You need accounts on Google Cloud, Neon and Vercel.

  1. Publish the CLI downloads

    Merge the standalone CLI changes into main, then push a version tag. GitHub builds the CLI for macOS and Linux and attaches it to a release.

    git tag cli-v0.1.0 && git push origin cli-v0.1.0

  2. Get the database connection strings

    In Neon, open your project and copy two connection strings: the pooled one (host contains -pooler) and the direct one. If you use the Neon project already linked to this repo, both are in .env.local as DATABASE_URL and DATABASE_URL_UNPOOLED.

  3. Create the Google sign-in client

    In Google Cloud Console, go to APIs & Services, then Credentials, and create an OAuth client ID of type Web application with this redirect URI:

    https://claude-tracker-inky.vercel.app/api/auth/google/callback
    • Keep the client ID and secret for step 5.
    • Google Workspace: set the consent screen to Internal. Personal Gmail accounts: publish the app, or add each teammate as a test user.

  4. Create the Vercel project

    Import rish-kun/claude-tracker into Vercel. In Settings, then Build and Deployment, set Framework Preset to Services and leave Root Directory empty. The dashboard address above must be the domain this project serves.

  5. Add the environment variables

    Paste this into Vercel's environment variables, then fill in the empty values.

    DATABASE_URL=
DATABASE_URL_UNPOOLED=
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=
SESSION_SECRET=
PUBLIC_URL=https://claude-tracker-inky.vercel.app
ADMIN_EMAILS=you@example.com
ALLOWED_DOMAINS=
ALLOWED_EMAILS=
AUTO_MIGRATE=true
    VariableWhat to put
    SESSION_SECRETA random string, made in this browser.
    ALLOWED_DOMAINSYour Workspace domain, like example.com, so anyone in it can sign in.
    ALLOWED_EMAILSIndividual addresses, comma-separated. Set this one, ALLOWED_DOMAINS, or both. With neither, the server won't start.
    ADMIN_EMAILSPeople who can see everyone's usage.

  6. Deploy and sign in

    Deploy, open https://claude-tracker-inky.vercel.app and sign in with your admin email. After teammates start syncing, each Claude account shows up in Settings. Give each one a name and choose its plan, so limits and costs are measured correctly.

Each teammate

About 5 minutes per machine. Send them this page, with the fields above filled in.

  1. Get access

    Each teammate needs read access to rish-kun/claude-tracker on GitHub, and Claude Code 2.1.295 or later.

  2. Install the CLI

    It's a single file that needs nothing else installed. Choose your machine: 

    gh release download --repo rish-kun/claude-tracker --pattern 'cctrack-aarch64-apple-darwin.tar.gz'
mkdir -p ~/.local/bin
tar -xzf cctrack-aarch64-apple-darwin.tar.gz -C ~/.local/bin

    If you don't have gh, download the file from the repo's Releases page instead. Files downloaded in a browser on a Mac also need xattr -d com.apple.quarantine ~/.local/bin/cctrack.

  3. Sign in

    This opens the browser to sign in with Google. On a machine without a browser, add --paste.

    ~/.local/bin/cctrack login --server https://claude-tracker-inky.vercel.app
~/.local/bin/cctrack status

  4. Add the Claude Code plugin

    Run these inside Claude Code. From then on, Claude Code won't start work until you're signed in, and it uploads usage after each turn.

    /plugin marketplace add rish-kun/claude-tracker
/plugin install cctrack@cctrack
Optional: make the plugin mandatory

With admin rights on a machine, save this as /Library/Application Support/ClaudeCode/managed-settings.json (macOS) or /etc/claude-code/managed-settings.json (Linux). The plugin is then always on, and teammates can't turn it off.

{
  "extraKnownMarketplaces": {
    "cctrack": { "source": { "source": "github", "repo": "rish-kun/claude-tracker" } }
  },
  "enabledPlugins": { "cctrack@cctrack": true }
}
